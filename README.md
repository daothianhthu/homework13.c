# 과제 13: 병합 정렬과 퀵 정렬의 성능 비교

## 1. 빌드 및 실행

```bash
gcc -O2 -Wall -Wextra main.c quicksort.c mergesort.c -o hw13
./hw13
```

- `main.c` : 데이터 생성, 복사, 시간 측정, 정렬 검증, 결과 출력
- `mergesort.c` : 병합 정렬 + 비교 횟수/메모리 측정
- `quicksort.c` : 퀵 정렬 (First / Random / Median-of-Three) + 비교 횟수/메모리 측정

n = 1,000 / 2,000 / 4,000 / 8,000 / 16,000 / 20,000 에 대해, 각 크기마다 같은 원본 배열의 복사본을 네 알고리즘에 사용한다.
모든 결과는 `isSorted()`로 오름차순 여부를 확인하며(`Sorted check` 줄), 실행 결과 모두 OK 였다.

## 2. 측정 방법

| 항목 | 측정 방법 |
|---|---|
| 비교 횟수 | 데이터 값끼리 비교하는 곳에서만 `(*comparisons)++`. 반복문 인덱스/종료 조건 검사는 제외. 퀵 정렬의 Median-of-Three 피벗 선택 비교(3회/호출)는 포함. |
| 실행시간 | 정렬 호출 직전~직후를 고해상도 타이머로 측정 (Linux `clock_gettime(CLOCK_MONOTONIC)`, Windows `QueryPerformanceCounter`). 데이터 생성, 복사, 출력, 검증 시간은 제외. 4개 알고리즘 모두 같은 방법/단위(ms) 사용. |
| 메모리 | 아래 계산식으로 최대 추가 메모리를 계산 (원본 배열은 공통 비용이므로 제외). |

### 메모리 계산 기준

재귀 호출마다 생기는 스택 프레임의 크기를 "매개변수 + 지역변수"를 담은 구조체의 `sizeof`로 추정하고, 재귀 최대 깊이(`maxDepth`)를 실행 중 기록하여 곱한다. 실제 컴파일러의 프레임(반환 주소, 레지스터 저장 등)과는 다를 수 있는 **추정값**이다.

- 병합 정렬 = `n × sizeof(int)` (임시 배열 `temp`) + `maxDepth × sizeof(MergeSortFrameEstimate)` + `sizeof(MergeFrameEstimate)` (최깊은 지점에서 호출되는 `merge()` 프레임 1개)
- 퀵 정렬 = `maxDepth × sizeof(QuickSortFrameEstimate)` + `sizeof(PartitionFrameEstimate)` (`partition()` 프레임 1개). 별도로 할당하는 배열은 없다.

두 알고리즘 모두 같은 방식(스택 프레임 × 깊이 + 말단 함수 프레임 1개)으로 계산하여 공정하게 비교했다. 64비트 환경에서 프레임 추정 크기는 각각 40바이트(Merge/Quick 재귀 함수, partition), 48바이트(merge)이다.

## 4. 분석

### 4.1 데이터 크기에 따른 비교 횟수 변화

n이 1,000 → 20,000으로 20배 늘 때 병합 정렬의 비교 횟수는 8,729 → 260,912로 약 29.9배, 퀵 정렬(First)은 10,019 → 367,370으로 약 36.7배 증가했다. n²이라면 400배가 되었을 것이므로 두 알고리즘 모두 n·log n 증가이며, n·log n의 증가율(20 × 14.29 / 9.97 ≈ 28.7배)에 가깝다.

절대 횟수는 병합 정렬이 모든 크기에서 가장 적었다. 병합 정렬은 항상 반씩 나누므로 비교 횟수가 약 n·log₂n − n 수준이다(n=20,000: 이론 약 265,000, 측정 260,912). 퀵 정렬은 피벗이 정확히 중앙에 오지 않아 평균 약 1.39·n·log₂n − 2.85n 번 비교한다(n=20,000: 이론 약 339,600). n=20,000에서 퀵 정렬은 병합 정렬보다 약 23%(Median3) ~ 41%(First) 더 많이 비교했다.

### 4.2 실행시간 차이

n이 작을 때(1,000~8,000) 병합 정렬과 퀵 정렬의 시간은 거의 같았고(예: n=8,000에서 0.563 vs 0.558/0.568/0.464ms), 1회 측정의 잡음 범위 안이라 우열을 단정하기 어렵다. n=4,000과 16,000에서는 오히려 병합 정렬이 더 빨랐다. n=20,000에서는 First(2.203ms)와 Median3(2.281ms)가 병합 정렬(2.430ms)보다 약 6~9% 빨랐다.

퀵 정렬은 비교 횟수가 더 많은데도 병합 정렬과 비슷하거나 약간 빠른 수준이다. 이유는 다음과 같다.
- 병합 정렬은 병합마다 `temp`에 쓰고 다시 `arr`로 복사하므로 원소 이동이 많다. 퀵 정렬은 제자리(in-place) 교환만 한다.
- partition은 배열을 순차적으로 훑으므로 캐시 지역성이 좋다.
- 시간은 비교 횟수뿐 아니라 이동/복사 비용의 영향도 받는다. 이 비용 차이가 퀵 정렬의 추가 비교 횟수를 상쇄한다.

n=16,000에서 Random(2.444ms)과 Median3(2.249ms)가 비정상적으로 느린 것은 비교 횟수(257,042, 252,339)가 First(255,020)와 비슷한 점으로 보아 알고리즘 때문이 아니라 측정 잡음(스케줄링, 캐시 상태 등)으로 판단된다. 정확한 비교를 위해서는 같은 정렬을 여러 번 반복해 평균을 내는 것이 좋다.

### 4.3 메모리 사용량 차이

n=20,000에서 병합 정렬은 80,688바이트, 퀵 정렬은 1,040~1,520바이트로 **약 53~78배** 차이가 났다. 병합 정렬은 n에 비례하는 임시 배열(`n × 4B` = 80,000B)이 필요해 n이 20배 늘 때 메모리도 약 18배 늘었다(4,488 → 80,688). 반면 퀵 정렬은 재귀 스택만 쓰고 스택은 재귀 깊이에 비례하므로, n이 20배 늘어도 640~1,000 → 1,040~1,520바이트로 거의 늘지 않는다. 퀵 정렬의 메모리는 피벗 분할 결과에 따라 재귀 깊이가 달라지므로 크기에 대해 단조 증가하지 않고 들쭉날쭉하다(예: First는 n=16,000에서 1,400, n=20,000에서 1,520).

### 4.4 피벗 선택 방법에 따른 차이

무작위 데이터에서 세 방법의 차이는 n이 작을수록 거의 없었다(n=1,000~4,000에서는 ±10% 이내이며 우열이 일정하지 않음). n=20,000에서는 First 367,370, Random 326,465, Median3 320,976으로 차이가 뚜렷해졌다. First 대비 Random은 약 11%, Median3는 약 13% 적다. 이번 실행에서 First가 이론값(약 339,600)보다 높게 나온 것은 첫 원소가 우연히 치우친 값이 자주 선택된 결과로 보이며, 무작위 데이터에서도 피벗이 나쁘게 걸리면 비교 횟수가 눈에 띄게 늘 수 있음을 보여준다. Median3는 3개 중 중앙값을 골라 극단적으로 치우친 분할을 피하므로 가장 적게 비교했고, 메모리(재귀 깊이)도 대부분 가장 작았다(n=20,000: 1,040B). Random은 `rand()` 호출 비용이 있어 시간이 약간 더 길었다.

차이는 데이터가 나쁠 때 더 크다. First 피벗은 이미 정렬된 입력에서 O(n²)이 되고 재귀 깊이도 O(n)이 된다. Random과 Median3는 이런 입력에서도 안정적이다. 이번 실험은 무작위 데이터만 사용했으므로 First의 최악의 경우는 관찰되지 않았다.

### 4.5 시간 복잡도와 공간 복잡도

| | 최선 | 평균 | 최악 | 공간 |
|---|---|---|---|---|
| 병합 정렬 | O(n log n) | O(n log n) | O(n log n) | O(n) (임시 배열) + O(log n) 스택 |
| 퀵 정렬 | O(n log n) | O(n log n) | O(n²) | 평균 O(log n), 최악 O(n) (스택) |

병합 정렬은 입력과 무관하게 항상 균등 분할되어 시간이 안정적이지만 O(n) 추가 메모리가 필요하다. 퀵 정렬은 평균적으로 빠르고 메모리가 거의 필요 없지만 피벗 선택이 나쁘면 최악 O(n²)이 될 수 있으며, 이를 완화하는 방법이 Random/Median-of-Three 피벗이다.

## 5. 결론

- 비교 횟수는 병합 정렬이 가장 적다(균등 분할).
- 실행시간은 두 알고리즘이 비슷하며, 퀵 정렬은 비교가 더 많아도 제자리 교환과 캐시 효율 덕분에 격차를 메운다. 1회 측정의 잡음 때문에 작은 차이는 우열을 말하기 어렵다.
- 메모리는 퀵 정렬이 압도적으로 적다. 병합 정렬은 O(n) 임시 배열 때문에 n에 비례해 증가한다.
- 안정적인 O(n log n)이 필요하면 병합 정렬, 메모리가 제한되고 평균 속도가 중요하면 좋은 피벗 전략(Median3 등)을 쓴 퀵 정렬이 유리하다.
